## Summary

The Financial Health Score module has been implemented as per the Day 10
specification document. The scoring model converts a user's financial
behavior into a 0-100 score with a corresponding status, based on six
weighted factors.

## Implementation Details

**1. Weighted Factors (Total = 100 points)**
- Saving Behavior — 25 points
- Expense Control — 20 points
- Budget Control — 20 points
- Cash Flow — 15 points
- Debt/Udhaar — 10 points
- Expense Growth — 10 points

**2. Formulas and Thresholds**
Each factor is calculated using its defined formula (saving rate, expense
ratio, budget utilization, cash flow, debt ratio, expense growth %) and
mapped to a score using the threshold tables from the specification.

**3. Overall Score and Classification**
The final score is the weighted sum of all six factors, classified into:
Excellent (90-100), Good (75-89), Fair (60-74), Needs Attention (40-59),
Poor (0-39).

**4. Insights**
Structured, rule-based insights are generated from the verified score
components (no financial numbers are generated by AI, in line with the
specification's requirement that all calculations remain deterministic).

**5. API**
Endpoint `GET /api/ai/financial-health/{userId}` implemented, returning
score, status, saving rate, expense ratio, budget status, cash flow,
expense growth, and insights — matching the API contract in the
specification.

**6. Edge Cases Handled**
Zero-income users, users with no transactions, users with no budget set,
negative cash flow, and missing previous-period data.

## Files

- `financial_health_scoring.py` — Scoring engine (all six factors,
  classification, insights, edge case handling)
- `financial_health_router.py` — API route

## Testing

The scoring engine was verified against the worked example in the
specification (saving rate calculation matched exactly). All edge cases
were tested individually and produce correct, stable output. The API
endpoint was tested and returns the expected response format.

## Notes
